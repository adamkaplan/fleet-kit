## Cause (clause 1)

cloud/launcher/end_hook.py reads `git status --porcelain -z --untracked-files=all` (line 31), keeps the paths that are not secret-looking, stages them all and pushes <worker>/wip. Its one JSON line {pushed, wip_branch, skipped, error} names only `skipped`, so a stray untracked file is saved without a word. Tests that write under the repository root create exactly such files: the writers (grep for open(..., "w"/"a"), write_text, os.makedirs in cloud/launcher/tests and cloud/worker/tests) include test_cloud_worker.py, test_cloud_stack.py, test_cloud_stack_wait.py, test_cloud_settings.py, test_preflight.py, test_git_token_renewal.py, test_token_read_at_call.py, test_stub_cleanup.py, test_app_token.py, test_orchestrator_agent.py, test_driver.py, test_run_record.py, test_reaper_managed.py, test_model_credential.py, test_cluster_token_refresh.py, test_issues_read.py, test_vault_check_pins.py, test_cloud_preflight_wired.py, test_cloud_k1.py and the worker tests test_token_table.py, test_entrypoint.py, test_guard.py, test_guard_table.py, test_plan_check_in_pod.py, test_cw_gh_comments.py, test_activity.py, test_reach.py (stub_server.py and fake_kubectl are helpers). Most already use tempfile; the implementer re-runs the grep and `git status` after a full chain run to find the ones that really land in the work tree.

## The two heads

The pre-stop hook of PR #1144 (branch cw/prestop-push) is `cloud/worker/cw-prestop`, a wrapper that runs `cw-end-hook --prestop`; the logic is the same cloud/launcher/end_hook.py, whose status calls are at lines 152 and 196 on that branch (allow-list design: only a closed set of paths is staged). Order: #1144 merges first; this change is built on the merged code and applies to both the end path and the --prestop path of that file. If #1144 is not merged, the work waits (no parallel edit of end_hook.py). The key is computed from the same status list that decides the save, so the allow-list stays the one authority for what is saved.

## Open choices (one recommendation each)

- (a) Declared set. A pod cannot know a declared set of files: nothing in the pod records which files a worker meant to keep. Recommendation: no declared set; the line names all untracked paths saved. Cost: a deliberate new file is listed too; the reader judges.
- (b) Format. Recommendation: `"untracked": [paths]` (at most the first ten, in sorted order) and `"untracked_more": N` (the count of the rest, 0 when none). With no untracked file the line is today's line plus `"untracked": []` and `"untracked_more": 0`. Cost: two keys instead of one. Paths with a newline or spaces are carried by the JSON string escaping; never content.
- (c) Which tests move to the temporary directory. Recommendation: all that write under the repository root (the list above, narrowed by the grep and a clean `git status` after the chain). Cost: a wider edit; each moved test keeps its assertions.
- (d) Scan test method. Recommendation: an AST scan of cloud/*/tests/*.py for calls to open() with a write or append mode and for write_text/write_bytes whose path argument is built from the repository root (a name such as ROOT or REPO, or __file__ based). Limit: a path assembled through a helper, an alias or a subprocess is not seen; the mutant planted file shows the scan sees the direct form only.

## Out of scope

Changing which files are saved or skipped, the secret-looking rule, the push, the branch name, the launcher, and any content of files in the line.

## Constraints

- PC-1: the earlier cloud tests keep their assertions and stay chained (shared contract of the test chain).
- PC-2: a secret-looking path is never saved and never listed as saved; only its name appears, under skipped (security rule).

## Risks and rollback

A key change is additive; a reader of the line that ignores unknown keys is unaffected. Rollback: revert the commit; the save is untouched. The end hook is a held path (it saves every worker's work): held for the Chief of Staff.
