## Cause (clause 1)

cloud/worker/opencode-worker.json has a top-level permission block (bash rules only) and a worker agent block; neither names the question tool. cloud/worker/agents/orchestrator.md front matter sets question: allow. A call opens a prompt on a headless pod that nobody sees, so the session waits until stopped. The report path (cw-cloud, cloud_cli.py KINDS) already carries a question kind, so a question has a route out.

## Test method

New cloud/worker/tests/test_question_denied.py: loads the JSON and the orchestrator front matter, checks the key literally ("question": "deny") at the top level, in the worker block and in the orchestrator definition, and compares every other permission against the base file (git show of the base, or a pinned copy of the other keys). Mutants (key removed at top level, removed in the agent block, allow, ask, another key altered) each assert the mutation applied before the check runs. Chained in bin/test-cloud-launcher.

## Open choices (one recommendation each)

- (a) Orchestrator agent: deny or keep allow. The code shows no path by which a person answers a cloud orchestrator: it runs headless in a pod like the worker, and its only outward channel is the report path. Recommendation: deny. Cost: an orchestrator that wants input must report a question and wait for the next assignment. If a reviewer finds an answer path, keep allow and state why in the file.
- (b) Key name for the pinned opencode release (2.0.28 on main; 2.1.4 once #1279 merges). Recommendation: the offline test pins the literal key "question" in the permission block (the name the release documents), and the live scenario S6 proves the agent reads it, since only a running agent can. Cost: offline alone cannot prove the agent honours the key; a rename in a later release is caught at the next live check.
- (c) Live method. Recommendation: a scripted tool call through a fake model endpoint (as the agent-pin smoke test does) that asks the question tool, in the new image and the previous one. Cost: needs the fake endpoint and both images available to the tester.

## Out of scope

Any other permission, the report path, the launcher, the entrypoint, the image build, and adding any new authority.
