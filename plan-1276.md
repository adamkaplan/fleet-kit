## Cause (clause 1)

Public reason: a security floor. The agent release built on Bun 1.4.4 or later is required; the earlier runtime embeds trust roots that are being withdrawn. cloud/worker/Dockerfile pins ARG OPENCODE_VERSION=2.0.28 with ARG OPENCODE_SHA256, checked by sha256sum -c before the unpack. The image's system bundle is not affected; only the agent's own embedded bundle is, so only a newer release removes the withdrawn roots.

## Test method

New cloud/worker/tests/test_dockerfile_agent.py, in the style of test_dockerfile_node.py on origin/cw/node-runtime: a problems(text) function over the Dockerfile with FLOOR = (2, 1, 3), plus mutants (old version, version spelled twice, checksum after the unpack, masked check, missing or short sha). A scanner test with a synthetic binary holding a synthetic certificate. Both are added to the chain in bin/test-cloud-launcher.

## Open choices (one recommendation each)

- (a) Floor as a tuple versus an exact pin. Recommendation: pin 2.1.4 and test the floor as >= (2,1,3), the first release on Bun 1.4.4. Cost: a later bump above the floor needs no test edit; a bump below it is refused; the pin itself changes on every bump.
- (b) Where the scan runs. Recommendation: in the lane's check (output in the PR comment) plus a test of the scanner; not a scan stage of the image build, because the repository must not hold the withdrawn list. Cost: the scan is not enforced on every later build; it is run at each bump by the lane.
- (c) Rollback. The previous image digest stays the rollback for workers; re-pinning 2.0.28 is not a rollback target for the floor. Cost: the old digest is kept in the registry until the new image has run live.
- (d) "The same results as the old one". The version string differs by definition; the other results (credential import, server start with a password, one answer through the fake model endpoint) are identical to the baseline recorded from the old binary. Cost: the old binary is run once for the baseline.

## Out of scope

Changing the launcher, the entrypoint, the model endpoint, the system bundle, or any other image layer; the arm64 build.
