## Cause (clause 1)

bin/test-cloud-launcher ends in one line, `if python3 A && python3 B && ... ; then echo RESULT: PASS; else echo RESULT: FAIL; exit 1; fi`, of more than forty commands. Every member that adds a suite appends to that line. Git sees two edits of the same line as a conflict, so every pair of concurrent members conflicts and each merge round re-resolved it by hand (about fourteen times in one batch). The completeness loop also greps the script itself (`grep -q tests/$n $0`), so the file is both the list and the checker.

## Pinned tests that read the chain (named, each changed only as far as the new form needs)

- cloud/launcher/tests/test_cw_minter_manifest.py (about line 166): the CHAIN-LAST pin reads the chain text and requires the minter manifest test to be the last entry. It must read the last entry of the list file instead; the assertion (that test is last) stays as strong.
- cloud/launcher/tests/test_cloud_pr_preflight.py: the CHAIN fixture string and the cases that write `bin/test-cloud-launcher` text into scratch repositories must write the new form (script plus list file) so the same cases (listed, missing, exception) still decide the same way.
- cloud/launcher/tests/test_cluster_token_refresh.py (about line 1089): runs the chain script; it must still run it and read RESULT: PASS, with the list file present in its scratch copy.
- cloud/launcher/tests/test_cw_names.py: the neutral-names scan covers the files by name; it must also scan the new list file (no name allowed that the script may not hold).
- cloud/launcher/tests/test_cloud_worker.py (about line 815): the path rule that names the script must also name the list file.
- bin/test-workflow-split: the workflow step that runs the chain; its shape check must keep the step running bin/test-cloud-launcher and still require its result line.
- bin/cloud-pr-preflight, step 1: reads the script text and checks that each test name appears in it (it depends on the "named in the file" form). It must read the list file for listed names and keep the same two output messages.
- Open pull requests that append to the chain: members open at the time take ONE last merge of the new form; the chain lines they add are converted by their merger (each becomes one line in the sorted list file).

## Open choices (one recommendation each)

- (a) Conflict-free design. Recommendation: a list file with one entry per line, kept SORTED alphabetically by path, each member inserting its entry at its alphabetical place. Two additions at different places merge cleanly; a plain append at the end would still conflict (two additions at the same position). The chain-last rule of the minter manifest test is replaced by a fixed final line that no member edits: the sorted block is followed by the minter manifest entry as the last line of the file, and the pinned test checks the last entry of the list file; the sort check applies to all lines before it. Cost: the execution order changes from today's. Every suite is independent (the chain runs each as its own process); a suite that depended on another's side effects would show up when the builder runs the sorted list once before opening the PR. The builder does that run and lists any suite that fails in the new order in the PR.
- (b) Where the list lives. Recommendation: bin/test-cloud-launcher.chain next to the script, read by the script; the completeness check reads the same file instead of grepping $0. Cost: one more file to keep in the path rules (see the worker test above).
- (c) Arguments and cd. Recommendation: an entry is a path; the script keeps its `cd` to the repository root and passes its own "$@" to each entry as today (python3 for .py, the file run as is for bin/test-cloud-cost-*). Cost: no per-entry arguments.
- (d) Failure behaviour. Recommendation: the first red stops, as today; the failing suite's own output is shown and then RESULT: FAIL with exit 1. Cost: later suites are not run after a red.

## Out of scope

Running suites in parallel; adding or removing suites; changing any suite's content; the exception reasons; the cost suites' content.
