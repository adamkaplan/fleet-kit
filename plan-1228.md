## The cause (clause 1, stated first)

A pod's own disk is deleted with the pod. A worker ended by an expired token (one-hour token) or a deadline strands its unpushed work; in one recorded case two hours of work sat unpushed in a kept pod and was saved only by copying a bundle out by hand. The persistent orchestrator pod of the token-role change is a one-replica StatefulSet whose only volumes are a memory-backed token volume, a scratch emptyDir and the read-only per-run secret; the agent keeps its session under the data directory on the memory-backed temporary directory (set in the worker entrypoint), so the session and the work tree live only as long as the pod. The pre-stop push (ask 1142) stays as the interim.

## Open choices (one recommendation each, with its cost)

- (a) Granularity: ONE disk per orchestrator pod (recommended; the StatefulSet's own volume claim template, named after the workload) versus one per worker. Cost of per-worker: a disk for every short run, far more claims against the 16-disks-per-node limit, and a retention sweep for each; a plain worker is short-lived and pushes. Per-orchestrator costs at most a few disks.
- (b) Size and class: default 8 GiB (a constant, overridable by a launch option up to a stated maximum of 32 GiB); storage class the cluster's default (Standard SSD, non-zonal nodes, so the claim follows the pod to any node); price used: 0.30 USD per month per 4 GiB = 0.075 USD per GiB per month, so the default disk is 0.60 USD per month and the 32 GiB maximum 2.40 USD per month. The class is a launch setting; an empty value means the cluster default. 16 disks per node bounds how many persistent lanes one node carries.
- (c) Stop or retire: KEEP the disk (recommended, so the lane resumes); a named flag (`--delete-disk`) or command (`delete-disk NAME`) removes it. Cost of delete-by-default: it recreates the stranding this ask exists to end. Retention constant: 7 days (RETAINED_DISK_DAYS). The reaper only REPORTS a retained disk older than it (name, size, age); only the named command, run by a person or orchestrator, deletes. Cost of keeping: about 0.075 USD per GiB per month until removed.
- (d) Resume: a launch of the same name finds the claim of that name and attaches it (the StatefulSet template names it, so the same name gives the same claim); a new name gets a new claim. A claim bound to a live pod is never given to a second one.
- (e) Opt-in for a plain worker: a launch option (`--disk [SIZE]`), off by default; without it the pod spec is identical to today. The orchestrator role gets the disk by default.
- (f) Operator Role: `persistentvolumeclaims` with verbs get, list, create, delete in namespace cw only (no patch, no watch, no wildcard, no ClusterRole); the pod's own Role gains nothing. Cluster step: `kubectl apply --dry-run=server -f cloud/k8s/operator-rbac.yaml` (and a dry run of a sample claim) first, then the owner's word, then the real apply. No new Azure role: the cluster's own class provisions the disk through its in-cluster provisioner.

## Out of scope

The pre-stop push (ask 1142, stays interim); snapshots and backups; a disk for every worker; resizing a live claim; deleting claims from the reaper; Azure roles or a new storage class.

## Areas touched, risks, rollback

Launcher (`cloud/launcher/cloud_worker.py`), worker entrypoint (data path onto the mounted disk when present), `cloud/k8s/operator-rbac.yaml`, README, tests. Held-PR area: cluster permissions and storage. Risk: a retained disk costs money until removed (the reaper report, cost line and cap bound it); a disk bound to a stale pod blocks resume (delete-disk is the way out). Rollback: revert the pull request and delete the claim Role verbs after the owner's word; existing claims stay and are removed with delete-disk.

## Open questions

None blocking; the owner may change the 8 GiB default, the 32 GiB maximum or the 7-day constant.
