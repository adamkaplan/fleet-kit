## Cause (clause 1)

In the launch, `hub` is true only when the hub channel URL or the registry secret is in the process environment. The launcher registers a hub entry for every orchestrator launch regardless. Without the setting the session step is skipped, the entry's session stays empty, the hub refuses the record as a bad agent record, and every message to that orchestrator answers 503. Found by the hub lane's live proof of the rebuilt image.

## Open choices (one recommendation each)

- (a) Proof that a worker launch is unchanged. Recommendation: compare the launcher argv list recorded by the fake launcher for a worker launch without the setting against a baseline captured from the unmodified code and stored as a fixture in the test. Cost: one small fixture to refresh if the launch argv legitimately changes later.
- (b) Where the documentation sentence lives. Recommendation: cloud/README.md, in "The orchestrator agent", where the hub setting is already described, with no edit to the interface document. Cost: docs/cloud-worker-interface.md does not repeat it (it already points to that README section).
- (c) Where the live check runs. Recommendation: the hub lane's probe pod on a rebuilt image, run by a tester, after merge. Cost: it waits for the image rebuild and the lane's pod; offline tests cover the rest meanwhile.

## Out of scope

Changing the launcher, the hub, its record validation, or the 503 answer; changing the hub setting for workers; the image build.
