# Cloud guard parity table

Every guard of the Mac agent, set against the cloud worker and CI: is it there, where is it enforced, and which law of the project it
serves (`FK-LAW-n`; the ids and one sentence each are in `docs/cloud-guard-law-ids.md`, a guard-parity list: the fuller law is a draft owned elsewhere, PR #544). This is the parity table that `FK-LAW-2` asks for when a new environment
ships. `cloud/tests/check-parity-table` checks its shape (no blank cell, a status on every row, an owner on every gap, only law ids listed in `docs/cloud-guard-law-ids.md`, the exact status words and a real item on a GAP) and runs inside `cloud/tests/test-cloud`. It checks the shape, not whether each claim is true: a reviewer reads the claims.

A row says `covered` only for code in the base this table is merged to; a row resting on an open stacked pull request reads `GAP (owner: ...; item: #NNN (open))` until that merges, and a one-line follow-up then flips it.

How to read a row:

- **Mac agent**, **cloud worker**, **CI**: what that environment does for the guard, or `n/a` with the reason.
- **Enforced where**: `server` (the repository's own rules), `token` (the credential's scope), `cluster policy`, or `local wrapper`
  (a convenience only; `FK-LAW-1` says a local wrapper is never the guard itself).
- **Status**: `covered`; `covered another way` (the cell says how); or `GAP (owner: WHO; item: WHERE)`, a gap written down and assigned.
