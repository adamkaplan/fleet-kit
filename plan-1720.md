## Design

In the test only (bin/test-switchboard, the one test), at the sha ddc022eb:
- slow() gets two events: entered (set right after the SEND entry is appended) and finished (set after real() returns).
- After self.clear() returns: assertFalse(finished.is_set(), "the clear did not wait for the blocked send") (event, replaces the elapsed < 1.0 decision); then entered.wait(10) as a CEILING; if not set, self.fail("the notice thread never reached the send: order=%s"). The existing sends assertion then sees an order with SEND in it.
- No sleep decides anything. Named pins (the only changed existing lines):
  - line 14115 OLD: `            return real(sender, recipient, text, **kw)` NEW: `            result = real(sender, recipient, text, **kw)` followed by added `finished.set()` and `return result`.
  - line 14122 OLD: `        self.assertLess(elapsed, 1.0, "the clear did not wait for the blocked send")` NEW: `        self.assertFalse(finished.is_set(), "the clear did not wait for the blocked send")`.
  - The began/elapsed lines stay (unused, not deleted).
- Scratch result of this design (copy at integration, nothing pushed as a product change): git diff shows 8 insertions, 2 deletions (the two pins) in bin/test-switchboard.

Mutant measurements on that scratch copy (single test):
- control (unmutated): exit 0.
- mutant 1 (neutralise_marker moved after notify_clear in impact_hold.py): exit 1, text "AssertionError: False is not true : the marker edit happened BEFORE the send was attempted: ['DELETE worker%3Ahold-impact', 'DELETE worker%3Amerge-captain', 'SEND chief-of-staff', 'PATCH 7']".
- mutant 2 (worker.start() skipped): exit 1, text "AssertionError: the notice thread never reached the send: order=['DELETE worker%3Ahold-impact', 'DELETE worker%3Amerge-captain', 'PATCH 7']", not the empty-list assertion.
(The old message wording "BEFORE" reads backwards for mutant 1; wording is left as is: changing it is a pin the implementer may add.)
