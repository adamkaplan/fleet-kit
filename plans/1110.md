## Plan (scenarios)

plan-format: 2
size: M (a new audited command with four refusals and a rate limit, one shared function used by the command and by the blocked-report pass, report text, one proposed permission line, docs, tests with five mutants; a few hours of agent time)
unchanged: none because this changes what the blocked report says and adds a resume path, and nothing else about delivery, holds or reports

### Cause (clause 1, stated first)
`blocked_kind` in `bin/fleet-switchboard` builds the report line for a blocked agent. For an ended turn with nothing open it returns the text "the Chief of Staff may resume it with one `poke`, which is audited". `cmd_poke` only asks the daemon for a pass: it takes no agent name, sends nothing and resumes no agent. The documentation (docs/switchboard.md, the blocked report section: "may resume the agent with one `poke`... a permission the Chief of Staff does not have by default") repeats it, and the permission list in `agents/opencode/chief-of-staff.md` has no `poke` allow, so the report names a command that does not resume, and the reader is not allowed to run it. The three disagree; the recorded cases (workers stuck 2 to 8 hours after a provider error, HTTP 499, until a person typed Continue in the pane) were left waiting for the owner. The send path (`cmd_send`, the engine's plan and deliver) holds an agent the terminal shows blocked (`hold_reason`), so `send` cannot be the resume either.

### Approach (what, not how)
One audited resume command, named with the agent, that sends the resume text to that agent's session only when its turn has ended and nothing is open. The report names that command (or says only the owner can resume it when something is open). The daemon's blocked-report pass calls the SAME function with the same rules and the same rate limit for a provider-error stop, once, before it reports. The grant is a proposal for the owner, never applied by this change.

### Done when (copied exactly from the ask)
Done when: (1) the cause is found and stated first from the recorded case (the first live blocked-agent report named `poke` as the way to resume an agent stopped by a provider error, while `fleet-switchboard poke` only asks the daemon for a pass, takes no argument and resumes no agent, and the Chief of Staff's permissions deny it anyway): the report text, the documentation line and the permission set disagree; (2) the report names a real resume command with the agent's name (a single audited command that sends the resume text to that agent's session only when its turn has ended and nothing is open), or says plainly that only the owner can resume it; (3) the permission of the Chief of Staff and of fleetkit (the two callers allowed) to run exactly that command, and nothing broader, is documented as the owner's grant and shipped in the agent definition's permission list as a proposal the owner accepts (it is never applied by this change); (4) the command refuses an agent that has an open permission request or question (that goes to the owner), refuses a session that is working, records an audit line naming who resumed whom and why, and is limited to one resume per agent per 10 minutes; (5) tests: each refusal, the audit line, the rate limit, and a mutant that resumes a working agent, one that skips the audit and one that ignores the rate limit fail; (6) the documentation line and the report text agree with the command; (7) when a blocked report shows an ended turn after a provider error (HTTP 499, ECONNRESET or a timeout in the turn's error text), the daemon resumes that agent ONCE by the same command and the same rules, audited, before it reports, and the report then says it did; a second stop of the same agent inside the 10 minutes is reported as today; a test with a mutant that resumes twice and one that resumes a working agent.

Rollback: revert the pull request; the audit lines and the rate record are ordinary state rows. The grant is a proposal, so reverting touches no live permission.
