plan-format: 2

### Cause (clause 1, stated first)
Recorded case: a local run of `ReviewCommentLineTests ReviewCommentEndToEndTests` wrote fake rows into the real state directory, and the real daemon then reported the real orchestrators dead. The end-to-end class is a plain `unittest.TestCase`, not the suite's isolating `Base` (`bin/test-switchboard`, `class Base`, about line 358, which sets `HOME`, `XDG_CONFIG_HOME` and `XDG_STATE_HOME` to a temporary directory in `setUp`). `GithubRig.__init__` (about line 7770) builds `World(test, agents=(), config=raw)` with no `state`, so `World.__init__` (about line 2446) has `state=None` and calls `self.state = sb.ensure_state_dir(state)`. In `bin/fleet-switchboard`, `ensure_state_dir(path=None)` (about line 905) does `path = Path(path) if path else state_dir_path()`, and `state_dir_path()` (about line 447) is `_xdg("XDG_STATE_HOME", ".local/state") / PROG`: with no isolation that is the real directory. `World` then writes `audit.jsonl` and `herdr-server.log` under it (`self.audit_path = self.state / "audit.jsonl"`, `empty_log.write_text("")`), and the rig's hub gets the same state. Files written: `audit.jsonl` and `herdr-server.log` in the real state directory, plus the fake orchestrator rows the hub and engine recorded there; those are what made the daemon judge the real agents dead. The marker `UNDER_TEST_ENV = "FLEET_SWITCHBOARD_UNDER_TEST"` (about line 1353) is set by the suite but is only used to refuse the real opencode, never to guard paths. The same default is also reachable through `config_path()` (about line 442) and the audit path built at about lines 7329, 10632, 17332 and 23960. The classes named in the ask were not found by name in this checkout's grep; the implementer must find every class that builds a `World` or `GithubRig` and is not derived from `Base` by the ast test (S4) and list them in the PR.

### Approach (what, not how)
Under `FLEET_SWITCHBOARD_UNDER_TEST`, a state directory, a config directory or an audit path that resolves to the real one (the real default, or any path the real daemon uses, compared after resolving symlinks) is refused with a named error, in `ensure_state_dir` and at every other place a path is built from the default. `World` and `GithubRig` refuse `state=None` unless the test is an isolating class. A test derives, by ast, every class that builds a `World` or a rig and fails when one is not derived from `Base`. The violating classes are fixed, the review-comment classes of PR #1304 first. The docs say how to run the suite safely. No other behaviour changes.

A class that fails only because it was not isolated is converted to `Base`, which is the point; a failure for any other reason is a defect of the change. Rollback: revert the pull request; no data is written.
