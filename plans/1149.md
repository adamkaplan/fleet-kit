### Cause (clause 1, stated first)
`bin/cloud_channel_server.py` (#1105, branch `hub/h1077-work`) defines `make_server(address, reviewer, inbox, audit)` and `serve(environ, reviewer, inbox, audit)`; its own header says "nothing is wired into the daemon". `cmd_run` in `bin/fleet-switchboard` (the service loop, around line 19030) starts the judge server (`start_judge_server`) and the pass loop but never calls `serve`, and no function builds a TokenReview reviewer or an inbox for `cloud_channel.handle`. The inbox contract `put_if_absent(recipient, dedupe_key, item)` has no implementation in the daemon: `Engine.send` (about line 5162) goes through `plan()` and `deliver()` (note, wake, hold, riders, key dedupe), a path the channel does not reach. `bin/decisions_pull.py` (#1108) reads a `decisions.json` that `publish_decisions(engine)` (about line 13010) writes to the state dir, but the listener serves only `POST /message`: nothing serves that file over the network. So a cloud agent cannot message through the daemon and the panel cannot read a cloud daemon's decisions.

### Approach (what, not how)
`cmd_run` starts the listener only when `FLEET_CLOUD_CHANNEL_LISTEN` is set (START point: after `build_engine`, next to `start_judge_server`; stopped with the daemon). It passes three injected dependencies: a TokenReview reviewer (Kubernetes TokenReview of the pod's service account token with the audience set; no key stored), an inbox adapter whose `put_if_absent` calls ONE function that `engine.send` also calls, and the engine audit (`engine._note`). That shared function holds the delivery rules (`plan()`/`deliver()`: note, wake, hold, riders, key dedupe); there is no second copy of the rules. The sender is the agent named from the verified pod identity (`cloud_channel.agent_of`), never a field of the body. A read-only `GET /decisions` on the same listener, authenticated by the same bearer review, returns the daemon's decisions in the shape `decisions_pull.py` `parse` reads (the content of `decisions.json`). Build base: origin/main plus the `hub/h1077-work` branch (#1105) and #1108's head. If #1105 merges first, rebase onto main and drop the listener commits; the daemon wiring is unchanged.

Risk: the shared function changes `engine.send` by accident (pinned by U1) or the reviewer trusts too much (S3, S5). A failing TokenReview refuses with 503, never lets a message through. A listener bind failure is audited and must not stop the daemon's passes. Rollback: revert the pull request; with the variable unset nothing runs, so it is also off by one unset.
