### Cause (clause 1, stated first)
The batch readers found this in the merged code, in `bin/fleet-switchboard`. `pane_health_pass` (about line 7133) counts a missing agent in its last loop (about line 7197 to 7202): `missing[name] = int(missing.get(name, 0)) + 1`, then `if missing[name] >= PANE_MISSING_PASSES and state != PANE_DEAD` it writes the dead state and the `fleetpane.dead` audit line. `PANE_MISSING_PASSES = 3` (line 6716) is a number of passes, about 10 seconds apart, so the guard is about 30 seconds, not a time, and it does not depend on how long herdr was really silent.

The list read that returned too little is `discover` (about line 4531, the call `self.herdr.agent_list()` at about line 4548): `Discovery.missing` (about line 3459) answers "not found: no herdr pane shows a v2 session named ..." for every agent that the list did not hold. A list that is empty, short or unreadable (a herdr restart, a timeout) is therefore read as "each agent is absent" and the loop counts one miss for every known agent in the same pass. The loop has no notion of a list gap: it never compares the size of the list to the number of agents known to be live, so three such passes mark them all dead at once. Recorded: at 16:36:50Z every named agent was "not found" in one pass, 14 agents were declared dead at 16:37:00Z although herdr listed all their panes.

Why the state was never cleared: the only recovery is in the live branch of the same function (about line 7160 to 7180): `fleetpane.recovered` is written only when the agent is seen in discovery AND its pane check is `due` AND the budget `PANE_CHECKS_PER_PASS` is not spent AND the new state differs from `prev`. The dead state written by the missing loop carries `at` of that pass, and nothing compares it with the time of the last list that showed the agent. In the recorded case no `fleetpane.recovered` line followed, so the dead state was still reported hours later. The plan's first task is to confirm from the code and the audit which of these conditions held (the check not due, the budget spent by many panes, or the pane id differing), and to state it in the pull request.

### Approach (what, not how)
A pass is judged HEALTHY or a LIST GAP before any miss is counted. A list gap is a list that is unreadable, empty, or lacks at least half of the agents known to be live. A gap counts no miss for any agent and writes one audit line that names the gap. An agent is declared dead only when it was missing from the list in healthy passes spanning at least 120 seconds (a time kept from the first healthy miss, not a count of passes); the audit line says how long. A dead pane that appears again in a healthy list is cleared in that pass with a `fleetpane.recovered` audit line, with no wait for the pane check schedule. A dead state older than the last healthy list that shows the agent is never reported. A pane really gone in healthy passes for the time is still declared dead.
