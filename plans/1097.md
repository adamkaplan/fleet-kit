### Cause (clause 1, stated first)
In `bin/fleet-switchboard` the load record is built near line 27109: `coders = [o for o in discovery.agents.values() if boss_name(discovery, o) == name and (o.fleet or {}).get("role") == "coder" and not coder_finished(...)]`, then `busy` and `idle` are counted from `c.status` (about line 27113) and `workers` lists the names. `discovery.agents` holds terminal agents and headless workers only. A cloud worker has an endpoint record under the cloud record directory and no discovered agent, so it is never in `coders` and never counted (the same split the file notes at `cmd_retire`, "not a discovered agent"). The panel therefore shows local workers only.

### Approach (what, not how)
Per lane, the load record gains a separate count of live cloud workers read from the cloud records: a record whose worker is finished or retired is not counted; a worker is attributed to the lane that owns it by the same boss rule the local coders use. The count is not added to busy or idle. The panel shows it marked as cloud beside the local count (`c1+2☁/4`); with zero cloud workers the text is byte-identical to today. The read is of files the daemon already reads or one bounded listing of the record directory (a cap on entries and on bytes per record). An unreadable directory leaves the local count showing and writes one audit line. No GitHub read, no new process.
