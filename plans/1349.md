### Cause (clause 1, stated first)
`TRIAGE_NEXT_RE` (`bin/fleet-switchboard`, about line 12895) is `^[ \t]*(?:next(?: steps?)?[ \t]*:|[-*][ \t]+\[[ xX]\])` (ignore case, multiline). It is the only reader of a next step: `triage_comment_facts` (about line 13152) sets a comment's `"next"` with it, and `triage_item_facts` (about line 13135) sets `next_body` with it. T3 in `triage_rules` (about line 13248) is quiet only if `item["next_body"]` or `any(c["next"] ...)`, with no date at all. T12 (about line 13273) reads neither: it is quiet only for an open sub-issue, `pending_text`, a pending proof or `triage_awaits_live`, so a comment line never silences it, and nothing there knows a date or an "awaiting batch" state (the `waiting` set of #921 covers only T1 and T11, and `link` for T12 is still built for it).

The form it fails to read: a standing line that does not start with `Next:` or `Next step(s):` followed at once by a colon. The real shapes, rewritten neutral: on #1165 the line `Standing line (26 Oct 07:55Z): the change is in batch 6 (pull request #1325: ready, waiting for the owner's clear). It closes when that batch reaches the default branch ... then the live line ...` starts with `Standing line (`, and the earlier `Next step (triage, 25 Oct): keep with the lane ...` has `(triage, 25 Oct)` between `step` and the colon, so the regex's `next steps?[ \t]*:` fails on it as well. On #1025 the line posted at the same time (26 Oct 07:51Z) has the same standing-line form. Neither matches, so for T3 `c["next"]` is False; for T12 the comment is never read. The date inside the line is never parsed anywhere, so even a matched line would silence nothing after or before the date. That is why both issues re-fired hours after the line: the rules saw no next step and no wait, and their own cooldown is not the date in the line. (Not the `IntentReader._cached` TTL: that cache serves intents, not triage.) A real shape of a case T3 judges: an ask, quiet for the SLA days, whose only comment is such a standing line.

### Approach (what, not how)
One shared reader of the standing line, used by T3 and by T12 (and by nothing else): from the item's comments (and body) it returns the date the standing line names, or the state "awaiting batch", or None. It reads the forms above: `Standing line (<date> ...):`, `Next step (<note>):`, and the existing `Next:` forms. While now is before the end of that date (UTC, day included, like `parked_until`) T3 and T12 are silent on that issue; from the day after, both judge as before. A date beyond a sane horizon (as `PARKED_MAX_DAYS`) or an unreadable one is not a silence. The latest standing line wins. "Awaiting batch" with no date silences until a newer comment or the merge of the batch, bounded by the same horizon. The reader is pure (text in, date or state out); no GitHub write; no change to the clear machinery.
