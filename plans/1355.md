### Cause (clause 1, stated first)
In `cmd_remind` (`bin/switchboard/reminders.py`, about line 660 to 690) the text is joined as `" ".join(args.text).strip()` and armed with `add_reminder(...)` whatever its length. Afterwards the only check is `if len(item["text"]) > TEXT_CAP:` (`TEXT_CAP = 4000`, line 74, "mirrors MESSAGE_CAP in bin/fleet-switchboard", line 1848), which only writes `warning: text is cut at 4000 characters: N characters over` to stderr and still prints the id and exits `EXIT_OK`: the reminder is armed whole, and the warning is the only sign. The cut happens later, on delivery: a due reminder becomes a fact for `compose` (`bin/switchboard/decision.py`, the marker `"\n[cut at %d characters]" % cap`, about line 194), which cuts the message at `MESSAGE_CAP` (4000) once its header is added. `Engine` delivery (`bin/fleet-switchboard` about line 2965) raises `MessageTooLong` only for a carried `send` fact; a reminder fact is not a `send`, so it passes the guard and is cut. A real run (to be repeated in a scratch HOME/XDG state, never the real one) of `remind a 1m <4,100 characters>` exits 0, prints the id and the warning, and the delivered text ends at `[cut at 4000 characters]`. Reported case: a long text delivered cut at 4,000 characters (an orchestrator of another lane). Duplicate copies are #1285's.

### Approach (what, not how)
Reuse the #1302 parts mechanism, not a second one: `finding_parts` / `finding_part` and `compose` in `bin/switchboard/decision.py` (PR #1315, branch `c1302`, open), which split an over-cap text on whole lines, split a longer line with a continuation mark, label each part, persist how many parts were delivered, and acknowledge a key only with the last part. A reminder over the cap is delivered through that path. Two entries:
1. `remind <name> <when> <text>` with text over 4,000 characters and no file is refused: exit status non-zero, a named reason that says to use `--text-file`, nothing armed (no row in reminders.json, no audit line).
2. `remind ... --text-file F` reads F (UTF-8, refused if unreadable, empty or not text), arms the full text, delivered in parts each under the cap, the reminder's key acknowledged only after the last part. Text of 4,000 or fewer characters from a file is one ordinary message.
The cap counts characters (not bytes), so multibyte text is neither cut inside a character nor miscounted.
