### Cause (clause 1, stated first)
In `cmd_launch` (`bin/fleet-switchboard`, line 13274) the brief is read by `brief = read_brief(args.brief_file, sys.stdin)` (about line 13346; the `--resume` path reads it at about line 13306 through `resume_brief.read`) and `--issue` is the argument declared at line 21492. The two are never compared: the brief text goes to the new agent as its first prompt, and `args.issue` only becomes `metadata.fleet.issue`. So a brief whose `ISSUE:` line or PR line names another issue, or whose `at head <sha>` is an old head of the PR, starts a coder, prover or tester on the wrong work. Recorded: adapted briefs carried a stale head or issue four times, and one tester would have read the wrong plan. Shapes, with neutral numbers: launch for issue #20 with a brief saying `ISSUE: https://github.com/OWNER/REPO/issues/20` and `PR #21 at head abc1234`.

### Approach (what, not how)
Before any pane or process starts (the same place the brief is read, after the repo checks), when `--issue N` is given the brief is scanned for an `ISSUE:` line, a PR line and an `at head <sha>` clause. An issue number that differs from N is refused, naming both numbers. A head sha that is not a prefix of (or equal to) the named PR's current head is refused, naming both. No such line: accepted, as today. Decision: when the PR's head cannot be read (a GitHub error, not a missing PR), the launch is REFUSED as unverified, never accepted, because a stale head passing silently is the failure being fixed; the reason tells the caller to retry or override. An override flag `--allow-brief-mismatch REASON` needs a non-empty reason, which is written to the audit line; with it the launch proceeds. The refusal exits non-zero and nothing is started.

### Done when (copied exactly from the ask)
Done when: (1) the cause is stated first from the launch code (it reads the brief but compares nothing); (2) launch with --issue N refuses, naming the mismatch, a brief whose `ISSUE:` line or PR line names another issue, or whose `at head <sha>` differs from that PR's current head (exit status non-zero, nothing started; an override flag that needs a reason); (3) tests with real brief shapes: a matching brief accepted, a stale head refused, a wrong issue refused, a brief with no such line accepted; (4) the docs say it.

### Work item 1: launch compares the brief with its issue and head
One item, as the Done-when above.

### Out of scope
Rewriting or repairing briefs; checking anything else in a brief; `send`, `handoff` and resume briefs; any GitHub write; the cloud launcher.

### Areas touched
`cmd_launch` in `bin/fleet-switchboard` (a held-PR area: the daemon file, unless the check lives in a small new module, preferred), `docs/switchboard.md` (launch paragraph), `bin/test-switchboard`. Not touched: templates/, shims/, workflows.

### Risks and rollback
Risk: a brief that mentions another issue in prose is refused wrongly; only the `ISSUE:` line, the PR line and `at head` are read, and the override covers the rest. A GitHub outage refuses launches that carry a head (S5); the override is the way through. Rollback: revert the pull request.

Stay on main.
