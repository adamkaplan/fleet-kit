### Cause (clause 1, stated first)
In `bin/fleet-switchboard`, `sweep_findings` (about line 13870) raises S5 from the decision rows: a decision with `tier == "cos"`, not a notice, whose `since` is at least `cfg["aged_cos_hours"]` old and which the owner's tier does not already hold (lines ~13944-13948). The clock is `parse_iso(d.get("since"))`: the time since the decision row was recorded (the hold or its last event). It never reads the pull request's gates: no call to the reading `cmd_gates` prints (CI, review, proofs, body), so a held pull request whose CI, review or proofs are still pending is reported as waiting on the Chief of Staff. The recorded S5 findings raised for not-ready held pull requests are listed in the pull request body from the sweep records, each with what was still pending (CI, review, proofs, body). The "who can clear it" reading exists as `clear_who` (used by `clear_line_post`, #946).

### Approach (what, not how)
S5 for a held pull request reads the same gate report as `gates`. Only when the single open enforced gate is the owner's clear is the pull request ready; the wait is counted from the first moment it was ready at its current head, kept per head in sweep state. A new head, or a gate that opens again, drops that moment and the wait restarts when it is ready again. A gate report that cannot be read yields no finding and is counted apart as "not checked". The finding names the head, the ready time and who clears it, once per head.

### Done when (copied exactly from the ask)
Done when: (1) the cause is found and stated first: the recorded S5 findings raised for held pull requests that were not yet ready (listed with what was still pending: CI, review, proofs, the body), and which clock S5 reads today (the time since the hold or the last event); (2) S5 reads the pull request's gates (the same reading as `gates`) and is raised only when the only open enforced gate is the owner's clear, and the wait is counted from the moment the pull request first became ready at its current head, not from the hold; (3) a new head restarts the wait, and a pull request that becomes not ready (a gate opens again) is no longer reported and its wait restarts when it is ready again; (4) a pull request whose gates cannot be read is not reported and is counted apart as "not checked", never raised; (5) the finding names the head, the time it became ready, and who clears it (the "who can clear it" line of the daemon, when it exists), and is raised once per head; (6) tests: not ready (CI pending, review missing, proofs missing, body missing: none raised), ready and under the threshold (not raised), ready and past it (raised once), a new head (restarts), a gate that opens again (cleared), an unreadable gate read (not checked); a mutant that counts from the hold, or raises a pull request that is not ready, fails; (7) the documentation describes when S5 fires.
