### Cause (clause 1, stated first)
`cmd_retire` in `bin/fleet-switchboard` has, for `--close`, a first branch: when discovery shows the worker as `seen.headless` it only sets `close_note = "headless: it has no terminal, so there is nothing to close"` and closes nothing. Every other `--close` goes to `retire_close_problem`, which judges only a terminal pane read from discovery: `boss_name(discovery, seen)` needs `seen`, then `seen.pane` and `seen.session_id`, and the pane is re-read by `engine.herdr.agent_get`. A headless worker has no pane, so the rule returns "may not close ... pane" or "has no pane and session ... nothing to close".
After a plain `retire`, `cmd_retire` calls `free_headless_record`, which runs `remove_record` (bin/agent_presence.py, `<state>/headless/`): the worker leaves discovery (`engine.discover` lists no record), so `seen is None`; `known_agent` finds only the retired.json entry and, with no record, `cmd_retire` raises "not a fleet agent this switchboard has seen". The boss rule then has no agent to judge. The text of `free_headless_record` states it: "the session itself keeps running in the service".
The retirement keeps what is needed: `headless_record_to_free` returns {session, url, created}, stored under `extra={"headless": ...}` in retired.json next to the recorded boss (`by`) and `session` (`registry_retired`, `retired_agent`). The service client already has `session_remove` (`session.remove`), called only by the launch rollback (about line 6620); `retire` never calls it. That is why the service keeps one opencode process per finished worker.

### Approach (what, not how)
`retire --close` for a headless worker (a live record, or the retirement's headless entry) ends its session through the service's session removal, judged by the same boss rule as a pane (operator, recorded boss, Chief of Staff for a direct report; never the caller's own session). The boss comes from the registry or, after retirement, from the retirement record (recorded boss plus session). Refused with a named reason while a turn is in progress (`session_active`) or activity is within `retire_idle_minutes`, unless `--force`; refused with `--force` too when a registered worktree holds uncommitted or unpushed work. One line says what was ended. A second call says "already ended" and changes nothing. One audit line `headless.closed` (who, session, reason). A one-shot `retire --close --all-retired` closes every retired-but-running headless session the caller may close, each judged by the same rule; one with unpushed work, a turn in progress or recent activity is skipped with its reason and the command lists counts. This frees the memory of the leftover opencode processes.

### Done when (copied exactly from the ask)
Done when: (1) the cause is found and stated first from the recorded case (three headless workers retired by their boss in the registry could not be closed by anyone: `retire --close` refused the boss and the Chief of Staff with "may not close ... pane" or "not a fleet agent this switchboard has seen"): which lines make `retire --close` judge only a terminal pane read from discovery, why a worker already retired no longer appears in discovery (so the boss rule has no agent to judge), and where the retirement keeps the headless record (session, url, created); (2) `retire <name> --close` for a HEADLESS worker (a live record, or the retirement's headless entry) ends its session in the service through the service's own session removal, judged by the same rule as a pane close (the operator, the agent's recorded boss, or the Chief of Staff for a direct report; never the caller's own session), refused with a named reason while the session has a turn in progress or activity within `retire_idle_minutes` unless `--force`, and says in one line what was ended; (3) a worker that was ALREADY retired is judged from the retirement record (its recorded boss and session), so the boss can end it after the fact, and a second call says "already ended" and changes nothing; (4) the unpushed-work rule of the pane close applies the same way (a worktree with uncommitted or unpushed work needs `--force`); (5) the audit records one `headless.closed` line with who asked, the session and the reason; (6) tests: a boss ends an idle headless worker; a non-boss is refused naming the rule; a worker with a turn in progress is refused without `--force`; an already retired worker is ended by its recorded boss; a second call changes nothing; a mutant that ends any session by name, one that skips the boss check and one that ignores the turn in progress fail; (7) the documentation says that `retire` alone only frees the record and `--close` ends the session.

The daemon file `bin/fleet-switchboard` is a held-PR area: the floor decides; expect the held path.

### Risks and rollback
Risk: ending a session that still works or holds unpushed work (destroys it): every unreadable fact (`session_active`, worktree facts, registry) fails closed with a reason, never ends. The bulk mode only skips on doubt. Rollback: revert the pull request; ended sessions are not restorable, `retire --undo` restores only the record.
