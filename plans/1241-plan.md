# Plan (scenarios): per-repository owner hold by class, with an exclude (#1241)

plan-format: 2
size: L. About a day of agent time: one pure function and one validator in bin/impact_floor.py (a held, top-tier file), a two-line plug-in in `pr_floor_report` in bin/fleet-switchboard, a docs section, and about 30 tests including mutants. The size comes from clause 5 (the fail-closed fallback and the kit-repository guard, each with several mutants) and from touching held machinery, not from the amount of code.
tier: clear/hold machinery. The PR holds for the owner, tier A, PR to main.
integration branch: stay on main

## Cause (clause 1, stated first)

Read on main (commit 70e17d4).

- The owner hold is the matrix's `owner_hold.top_tier_paths` (docs/review-laws/impact-matrix.json: classes `credentials`, `identity`, `authority`), kit-wide. `impact_floor.owner_hold_rule` reads it, `impact_floor.top_tier_hits(paths, matrix)` matches the changed paths against it, and `impact_floor.owner_decide` turns the hits into reasons `top tier path (<class>): ...` and returns "hold". There is no exclude and no repository argument anywhere in that chain: `top_tier_hits` takes only `paths` and `matrix`.
- A repository's own entry `impact_floor.repos."<owner>/<repo>"` (`globs`, `exclude`, `force`) is read by `impact_floor.floor_for(repo, config)` and applied by `impact_floor.floor_paths`. The result goes to `owner_decide` as `floor_hit`, which only adds the "second-review" line `floor: N path(s) outside the top tier ask for a second independent review`. It never produces "hold". (`impact_floor.decide` is the older floor decision and is the same: second review.)
- The hold is applied by `apply_impact_hold` and `_apply_impact_hold_locked` in bin/impact_hold.py, which take the report built by `pr_floor_report(engine, repo, number, rated_pairs)` in bin/fleet-switchboard. That function calls `floor_for`, `floor_paths`, then `owner_decide(matrix, paths, ...)`. This is where a per-repository hold plugs in: the one call to `owner_decide`, which must also receive the repository's hold entry (a new argument, default none, so every existing caller and fixture is unchanged). bin/impact_hold.py only reads the report's decision and reasons, so it needs no change.
- The machinery lists sit inside `owner_decide` and are independent of `top_tier_hits`: `impact_floor.clear_code_paths(matrix)` (`owner_hold.delegated_clear.clear_code_paths`, always held), the matrix `never_carried_paths` (`impact_floor.carry_never_paths`, read by bin/impact_hold.py at the carry sites), `narrow_by_diff`, and the closure rule (`owner_hold.delegated_clear.closure_files`, enforced in bin/delegated_clear.py `refusals`/`closure_refusals`, which bin/impact_hold.py reaches through `delegated_clear_pr_checks`). Keep these running for every repository named by an entry or not.
- The configuration check: `impact_floor.validate(raw, source)` calls `impact_floor.validate_config(raw)`; bin/fleet-switchboard `load_runnable_config` calls it by the module's declared `CONFIG_KEY = "impact_floor"` (config_declarations). Today `validate_config` refuses any key of a repos entry other than `globs`, `exclude`, `force` ("has key(s) this tool does not read"), and requires non-empty `globs`. That is where `hold` and `hold_exclude` are added.
- The default floor `impact_floor.default_floors()` / matrix `owner_hold.floor` names the kit repository (`adamkaplan/fleet-kit` in the matrix; the plan treats its name as data read from the matrix, never copied into code).

## Constraints

- PC-1: The code carries no repository name and no path list of its own; the kit-wide paths, the kit repository's name and every machinery list are read from the matrix (the matrix's own rule: "the code reads this block and has no path or class list of its own").
- PC-2: Fail closed. Anything unreadable, malformed or unknown about an entry at decision time falls back to the kit-wide default (`top_tier_paths`), with the reason `impact_floor.repos.<repo>.hold unreadable or invalid (<why>): kit-wide default applied`; never to an empty hold.
- PC-3: The kit repository's machinery (`clear_code_paths`, `never_carried_paths`, the closure files, `narrow_by_diff`) is evaluated after, and independent of, any entry. An entry only narrows the top-tier class hold of its own repository; it never reduces these lists, for any repository, including an entry written under the kit repository's name.
- PC-4: A repository with no `hold` key takes the exact old code path; the call to `owner_decide` is unchanged for it, so every existing fixture gives the same decisions and reasons byte for byte.
- PC-5: The `execution` class has no kit-wide counterpart; it holds only for the globs the operator lists. Database, schema and container changes are never a `hold` class; the independent impact rating decides them (the rating's own hold still applies in an entry repository).
- PC-6: An empty list, or a missing class, in an entry holds nothing for that class (not hold-all); a `hold` object with all four classes empty or absent is valid and holds only by rating and by the PC-3 machinery.
- PC-7: Examples, tests and docs use only neutral names (`acme-org/widget-api`, `acme-org/widget-web`, `deploy/**`, `auth/**`); the docs test fails on a real owner or repository name outside the kit's own.
- PC-8: Path matching reuses `impact_floor.matches` / `canonical` / `escapes` (one matcher); a path that escapes the repository still holds, as today.

## Where the new code goes (what, held for the owner)

- `impact_floor.validate_config`: allow `hold` and `hold_exclude`; refuse by key; refuse a machinery overlap in `hold_exclude` using the matrix lists.
- A pure `impact_floor.entry_hold(config, repo)` reading the entry (returns the entry, an "invalid" result with the reason, or None) and `owner_decide(..., entry=None)` applying it in place of `top_tier_hits` only for the top-tier path hold; all machinery code after it unchanged.
- `pr_floor_report` in bin/fleet-switchboard: pass the entry. Tests: tests for impact_floor, a report test, a docs test. Docs: one section in docs/switchboard.md.

## Out of scope
