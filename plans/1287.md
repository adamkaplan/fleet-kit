### Cause (clause 1, stated first)
Today the daemon's comment event path is `_wh_issue_comment` (`bin/fleet-switchboard`, about line 15343), which for action "created" calls `_comment_item` (about line 15255). `_comment_item` drops a comment with no id, no number or a fleet signature (`signed_by_fleet`), and otherwise builds one generic `github.comment:<id>` item whose summary is "@login commented on #N: <text up to 400 characters>". It does not look at whether #N is a pull request, does not read the first line, and addresses no lane's orchestrator. The same function is reached from the poll path (about line 16489). Recorded case: readers' review comments were posted on pull requests and no message told the lane's orchestrator, so a "changes requested" verdict was read hours later.

### Approach (what, not how)
A new comment on an open pull request whose first line matches `^Review of [0-9a-f]{40}` is delivered once to the orchestrator of the lane that owns the pull request, as one line: number, 12-character head, verdict (APPROVE, CHANGES REQUESTED, else UNKNOWN). No comment text is copied. Closed or merged pull requests, the author lane's own comments and non-matching comments are not delivered. Deduplication is by comment id, kept across a restart; an edit is not a new comment. The delivery uses only the data of the comment event the daemon already receives and writes nothing to GitHub.
