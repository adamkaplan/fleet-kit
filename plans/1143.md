### Cause (clause 1, stated first)
`cmd_charter` in `bin/fleet-switchboard` identifies its caller with `move_caller` and then `charter_set_refusal(caller, role)`. That function already lets the operator (a plain shell) and a caller whose role is "chief-of-staff" through, and refuses every other agent. So the code is not what blocked the Chief of Staff: the block is her definition. `agents/opencode/chief-of-staff.md` lists allowed shell commands one per line (`fleet-switchboard move *`, `reassign *`, ...) and has no `charter` entry, so the host refuses the command before the daemon sees it; the copilot variant (`agents/copilot/chief-of-staff.agent.md`) lists tools only (`bash`, ...), with no per-command list. Nine orchestrators' registry `charter` therefore stayed unset until the owner typed nine commands; registration of their workers' items was refused with "its parent chain does not reach the orchestrator's charter". The second gap is in the guard: `registry.set_charter` refuses only an unknown, retired or non-orchestrator row and a malformed value; it never checks that the issue is a native sub-issue of the repository's root, that another orchestrator holds it, or that an already-set charter is being changed (it overwrites silently). The audit line `charter.set` records old and new and the caller, but the output does not read the row back.

### Approach (what, not how)
Add the guard to the Chief of Staff's path (not the operator's): refuse, with a named reason, a non-orchestrator, an issue that is not a native sub-issue of the repository root or is already held by another orchestrator, and a change of a set charter unless the caller passes the existing `--replace` reason. Every use writes one audit line (caller, lane, old, new; refusals too). The command prints the registry row after writing. The permission is a diff in the pull request, `fleet-switchboard charter set *` with a comment that it records an orchestrator's own charter only, in the one-line form of the neighbours; the owner applies it. The pull request itself changes no permission in force.

### Done when (copied exactly from the ask)
Done when: (1) the cause is found and stated first from the recorded case (the registry's charter of nine lane orchestrators stayed unset because the command that sets it is allowed to no agent: tester and prover registrations of those lanes' work items were refused with "its parent chain does not reach the orchestrator's charter" until the owner typed nine commands): the command, where it checks its caller, and the Chief of Staff definition's permission list; (2) the Chief of Staff definitions (the one for the terminal agent and the one for the other host) gain exactly one allowed command, `fleet-switchboard charter set *`, in the same one-line form as the existing entries, with a comment that it records an orchestrator's own charter only; (3) the command refuses, with a named reason, a lane that is not a registered orchestrator, an issue that is not a native sub-issue of the lane's repository's root or that another orchestrator already holds, and any change of a charter that is already set unless the caller passes the existing `--replace` reason; (4) every use is audited with the caller, the lane, the old and the new charter; (5) the read-back (the registry's row) is shown by the command's own output, so no second command is needed; (6) tests: the definition's permission list holds exactly the one new entry and no wider pattern, each refusal, the audit line, and a mutant that allows `charter *`, one that skips the already-held check and one that accepts a non-orchestrator fail; (7) the documentation states the permission and who grants it. The permission change is the owner's yes: this ask delivers the diff and the guard, and the owner applies or declines it.

Risk: a guard that is too strict blocks a legitimate new lane (the refusal names its reason and the operator keeps the `--replace` path); a permission line wider than one command. Rollback: revert the pull request; registry rows it wrote are ordinary rows and the audit lines stay.
