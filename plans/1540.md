### Cause (clause 1, stated first)
The choice is made at `bin/fleet-switchboard` about line 2991: `delivery = "queue" if resume and not fault("steer-not-queue") else "steer"`, then `busy = resume and not interrupt and steers_into_turn(self.config, observation, carried, discovery)`, and only `if busy: delivery = "steer"`. `steers_into_turn` (`bin/switchboard/decision.py` line 80) returns true only when `config.get("send_to_working", "steer") == "steer"` AND `observation.status == "working"` AND some carried fact has `kind == "send"` whose `fact.sender == boss_name(discovery, observation)`. So the only thing that steers is a `send` from the recipient's own boss. Everything else always queues (after the turn): a peer `send` (sender is not the boss), a reminder (kind is not `send`), and any other kind. The `send_to_working` key (default "steer", `DEFAULTS` line 366, checked line 617) only switches the boss rule on or off; it has no notion of how long the turn has lasted. Recorded case: on 29 Oct about ten messages sent 01:50-02:23Z to one orchestrator surfaced 08:33-09:00Z because every peer send and reminder went as `delivery=queue` while a boss's send steered at once. No turn start exists on `Observation` (line 1971: only `idle_at`, `created`, `last_human_prompt`), so a turn age has no recorded source today.

### Approach (what, not how)
A new config key (name chosen in the work item; default off/0) holds a number of minutes. When it is on, the recipient is working, and its current turn started more than that many minutes ago (from a recorded turn start, never guessed), a peer `send` and a reminder are delivered as steer like a boss's, and the audit detail carries `busy: true` and the turn age. Off, a younger turn, or an unknown age: the decision is exactly the old one. Stop/hold orders, reports and orders are not touched. An idle recipient gets the wake as before. The turn start is read from what the system already records for the session; where none is recorded the age is unknown and counts as young.

A later `send --file` ask should REUSE the one function `read_text_file` and build after #1315 and #1355 land. This ask does not depend on them and does not touch that path; the mismatch is raised for the Chief of Staff in Open questions.
