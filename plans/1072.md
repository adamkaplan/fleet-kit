### Cause (clause 1, stated first)
`Engine._discover` in `bin/fleet-switchboard` calls `self.herdr.agent_list()` on every pass. When herdr is missing the call raises `HerdrError`, and the handler appends `"herdr unreachable: ..."` to `found.problems` before calling `_discover_headless`. `Engine.discover` then calls `read_mark(self, "agents", not problems, ...)` (#805), so any problem marks the agents input not whole. The result for a cloud-hosted orchestrator with no herdr is a standing "herdr unreachable" problem on every pass, and destructive steps that need a whole agents input are skipped via `whole_skipped`. Records alone are enough to discover agents: the registry plus `_discover_headless` already work without herdr. Code that assumes a pane (`render_badges`, which already skips `not observation.pane`, plus the pane reads and toasts) must be checked for pane-less agents.

### Approach (what, not how)
A config key with a neutral default (off) makes discovery skip the multiplexer. When on, discovery reads the registry and the headless and cloud records only, raises no "herdr unreachable" problem, and counts the agents input whole when those records were read without error. Agents with no pane get no badge, no toast delivery to a pane and no pane read, and none of these is an error. With the key off, nothing changes.
