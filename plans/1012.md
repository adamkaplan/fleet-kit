### Cause (clause 1, stated first)
The `permissions:` block of `agents/opencode/chief-of-staff.md` starts with `{action: "*", resource: "*", effect: deny}` (line 9) and allows only listed shell commands (the pipe readers `tr`, `cat` and others, then `fleet-switchboard ...`). It has no `sed` rule, so every `sed` call falls to the base deny. The reads the Chief of Staff cannot do: a line range of a long file (`sed -n '120,180p' file`) and the lines of a log that match a pattern (`sed -n '/ERROR/p' log`); `read` takes a whole file and `grep` gives matches without a range. The test class `TestChiefOfStaffNativePermissions` (`bin/test-switchboard`) evaluates the list with `evaluate(rules, action, resource)`: whole-value glob, the LAST matching rule decides, a trailing ` *` also matches the bare command. The installed copy is the rendered form of the same file (`__PROVIDER__/__MODEL_ID__` filled in) and carries the same absence; it is checked read-only here and re-rendered by the operator after the merge.

### Approach (what, not how)
Allow `sed` only in the three spelled-out reading forms on a file and the same three on standard input in a pipe, as globs. Then deny, AFTER the allows, every spelling that can write, run or read another file: `-i`, `--in-place`, `--in-place=SUF`, combined short options holding `i` (`-ni`, `-in`), `-n -i`, `-s`/`--separate` with a write, `-f`/`--file`, a second `-e`/`--expression`, any script holding `w`, `W`, `e`, `r`, `R` as a command or as an `s///` flag, a newline in the script, a here-document, a semicolon that chains a command. The deny list is derived from the sed manual's option and command lists; `y`, `z`, `F`, `=` stay denied because the three allowed forms do not need them (the ask allows them only if listed and read-only: none are). Why `sed -n` alone is not read-only: `-n` only silences output, a `w file`, `e` or `r` command still writes or runs. Globs cannot parse sed, so the rule is a fence of listed spellings: the test derives them from the manual and the docs say the list is not a parser.
