## Plan (scenarios)

plan-format: 2
size: M (a kind field on the daemon's panel items, one symbol table and one short-code function in the panel plugin, two docs lines, tests per kind with five mutants; a few hours of agent time)
unchanged: the rows' text and ordering, the row links (`urlOf`, `safeUrl`) and the click's opening of the item, the panel's own GitHub reads, because only a leading marker is added and the clipboard text changes

### Cause (stated first, from the code)
Two asks on one panel, planned together. Today a row carries no kind. The daemon builds the panel's items in `derive_decisions` and writes them to `decisions.json` (`bin/fleet-switchboard`, near line 11623; the issue items are built near line 10925 from `hub.awaiting_listing()` with `"kind": "issue"`, the pull-request rows are `"kind": "captain"` near line 30678 and `"kind": "notice"` heads-ups). Nothing in those items says whether an issue has a plan comment, so the plugin cannot tell an issue with a plan from one without. In the plugin (`plugins/fleet-decisions-tui/decisions.mjs`) `isPrRow` already separates pull-request rows from issue rows, `entryOf` and `factsSegments` draw the row with no kind marker, and `urlOf` builds the row link from `repo` and `ask` or `number`. In `tui.tsx` the click handler `copyLink` runs `safeUrl(raw)` and then `api.renderer.copyToClipboardOSC52(url)`, so a click copies the URL; the OSC 8 link (`<a href>`) is what opens the item. No function builds a short code from the repository's name and number, and the docs (`docs/switchboard.md`, "Clicking a row (issue 66)") say a click copies the link.

### Approach (what, not how)
Item 1: the daemon adds a kind to each panel item (pull request, issue with a plan, issue without one, or unknown), from data it already holds or one bounded cached read per issue. The plugin keeps one table of three symbols (plus a neutral marker for unknown) and prefixes each row. Item 2: one function builds `<repo name>:#<number>` from the row's repo (owner dropped) and number; the click copies that code and not the URL, and opening the item is unchanged. The docs give the legend and say what a click does.

### Work item 1: kind marker on each panel row (ask #1094)
Done when: (1) every row of the right panel (the Decisions panel) starts with one emoji for its kind: proposed 🔀 pull request, 📋 issue with a plan, 📝 issue without one (the owner may change them; the three symbols live in one table in one place); (2) the kind is derived from the item itself: a pull request is a pull request; an issue is "with a plan" when a plan comment of the ask exists (the same reading the plan checks use for "the plan comment"), otherwise "without one"; a row whose kind cannot be read shows a neutral marker and never a wrong kind; (3) deriving the kind adds no GitHub read per refresh beyond the reads the panel already makes (the plan state comes from data the daemon already holds or one bounded, cached read per issue); (4) the legend is one line in the docs; (5) a test pins each kind (pull request, issue with a plan, issue without a plan, unknown), a mutant that shows the same emoji for all kinds, one that marks an issue with a plan as without one, and one that drops the emoji from a row fail; (6) the existing rows and their ordering are otherwise unchanged.

### Work item 2: a click copies the short code (ask #1096)
Done when: (1) a click on a row still opens the item in the browser, unchanged; (2) the same click copies the short code `<repository-name>:#<number>` (for example `fleet-kit:#935` or `widget-service:#12`) and no longer copies the URL; (3) this holds for all three kinds of row (a pull request, an issue with a plan, an issue without one), shown by a test per kind with a mutant that copies the URL instead; (4) the short code uses the repository's own name without its owner, and the code is built in one function so every row uses it; (5) the docs say what a click does.

### Out of scope
Any change to the order or text of the rows beyond the marker; the OSC 8 link and `safeUrl`; new GitHub writes; the hold decision.

### Areas touched
`plugins/fleet-decisions-tui` (`decisions.mjs`, `tui.tsx`, a test file next to `health.test.mjs`), the daemon's panel items in `bin/fleet-switchboard` (a held-PR area: the daemon file), `docs/switchboard.md` (the "Decisions (PR 14)" section). Not touched: templates/, shims/, the matrix.

### Risks and rollback
Risk: an extra GitHub read per refresh if plan state is not cached (S3 counts reads); a short-lived stale kind within the cache's ttl; a repo name with an owner left in the code (S9). Rollback: revert the pull request.

Stay on main.
