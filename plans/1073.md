### Cause (clause 1, stated first)
Cloud workers are outside discovery. `Engine.discover` in `bin/fleet-switchboard` builds observations only from the multiplexer's agent entries, so a cloud worker (no pane, no local session) is never observed. Its records live in the cloud record directory, which only `status_extra` in `bin/cloud_worker.py` reads, and only when `status` is asked, plus the separate reaper service. `finish_pass` runs its per-pass ticks (`prune_delivered_reminders`, `friction_tick`, `load_tick`, `prune_report_riders`, `publish_decisions`, `write_catching_up`, `health_write`), each in try/except calling `engine._failed(...)`; none looks at cloud records. So a cloud worker's report and state are seen by nobody between `status` calls. The same gap blocks #1020 (a cloud worker's report reaching its lane): the tick built here is the one #1020 uses; nothing is duplicated.

### Approach (what, not how)
One `cloud_watch_tick(engine, discovery)` runs once per pass inside `finish_pass`, in its own try/except with `engine._failed("cloud-watch", "cloud-watch", err, report)`, like its siblings. It reads the cloud records with bounded reads (a cap on records and bytes per pass; a cap hit is audited once, not an error). It starts no process and no thread. It exposes the read result so #1020 can attach report delivery without a second read. The tick is read-only on records unless #1020 asks otherwise.

### Out of scope
Delivering a cloud worker's report to its lane (#1020 builds on this tick); the reaper service and its schedule; launching or retiring cloud workers; any new GitHub call; changing discovery for local agents.

### Areas touched
`finish_pass` and a new `cloud_watch_tick` in `bin/fleet-switchboard` (HELD area: the daemon file); a read helper in `bin/cloud_worker.py`; `docs/switchboard.md`; tests in `bin/test-switchboard`. No template, shim, plugin or matrix file.

### Risks and rollback
Risks: a huge or corrupt record directory slows the pass (bounded reads, per-record errors skipped and counted); two builders (#1020 and this) each adding a read (one shared function). Rollback: revert the pull request; the tick writes no state of its own.
