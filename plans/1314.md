### Cause (clause 1, stated first)
The Python 3.15 repair (PR #1312) put a bounded-depth scan on the cloud record readers. Two other readers of record text were not covered. `load_record` in `bin/agent_presence.py` (it calls `read_record`, which does `record = json.loads(raw.decode("utf-8"))` at about line 139 and catches only `(OSError, ValueError, UnicodeError)`), and the reader of record text in `bin/switchboard/reminders.py` (the ask names it `read_record_file`; in this checkout the matching `json.loads(path.read_text())` is in `read_reminders`, about line 36, catching only `(OSError, ValueError)`). Neither has a `RecursionError` catch and neither bounds the depth, so a deeply nested file either raises out of a pass or is refused only on interpreters whose recursion limit trips as a `ValueError`-family error. The refusal depends on the Python version. The existing scan test lists its readers by hand, so a reader missing from the list is never noticed. Note for the worker: the cloud repair's shared helper was not found by name in this checkout (`grep -rn "bounded" bin` finds only `decisions_pull.py` `clean(value, depth)` and the `RecursionError` catches in `cloud_way_back_check.py` and `decisions_pull.py`); the worker first re-reads the merged PR #1312 on the integration branch and names the helper and lines in the PR body.

### Approach (what, not how)
One shared bounded-depth parse for record text, with one named depth limit. Both readers use it and refuse a record nested deeper than the limit with the same skip kind, on every Python, never raising. A record nested exactly at the limit parses. The scan test derives the readers from the source (any `json.loads`, `json.load` or `from json import loads` of record text in `bin/`) and fails when one is not in its table.

### Done-when (copied exactly from the ask)
Done when: (1) the cause is stated first from the code (the repair for Python 3.15 added a bounded-depth scan to the cloud record readers; two other readers of record text were not covered: `load_record` in `bin/agent_presence.py` and `read_record_file` in `bin/switchboard/reminders.py`, the second with no `RecursionError` catch at all); (2) both readers use the shared bounded-depth parse and refuse a record nested deeper than the named limit with the same skip kind, identically on every Python (tests with a 30000-deep file); (3) a record nested exactly at the limit parses and one deeper is refused, for each reader; (4) the scan test derives the list of readers from the source (any `json.loads`, `json.load` or `from json import loads` of record text in `bin/`) instead of a hard-coded pair, and fails when a reader is missing from its table; (5) tests with mutants (the scan removed from each reader) and the docs say it.
