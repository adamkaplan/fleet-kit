### Cause (clause 1, stated first)
This is a tightening-only follow-up of the merged charter set guard. In `cmd_charter` (`bin/fleet-switchboard`, about line 26209) the guard reads `engine.intents.parent(value, repo0)` and, for an issue with no parent, `engine.intents.issue(value, repo0).labels` (about line 26212); `guard` (about lines 26217 to 26236) refuses with "is not a charter" when the orchestrator label is missing. The batch readers found that 3 of 12 mutants of that guard survive: the rig's fakes ignore the `repo` argument of `parent(` and `issue(`, so a build that reads the wrong repo is not caught. The label read goes through `IntentReader._cached` (about line 18845, key `("issue", repo, number)`, kept for a ttl), so a stale label can be served; the mutants and the fakes must pin the repo and the cache. For the delivery question of this ask, the same discipline applies: the table of measured answers is the source, and a test derives from it, so a fake that ignores a form cannot pass.

### Approach (what, not how)
Measure on a throwaway v2 session which delivery starts a turn in each case; record the table and a fixture; make a fake v2 reproduce each row; the daemon's wake to an idle agent uses the form that starts a turn, with the #1337 net unchanged. Fakes in the rig take and check the repo they are asked about, and a test shows the label read is not served stale from the ttl cache.

### Done when (copied exactly from the ask)
Done when: (1) a throwaway OpenCode v2 session (created for the measurement, named so it is never mistaken for a fleet agent, removed afterwards through the service's own removal) is driven through these cases with the daemon's own client: an idle session after a normal turn, an idle session after a turn that ended with a provider error, and a session that is working; for each, a message is delivered with each combination of `delivery` (`queue`, `steer`) and `resume` (true, false) and as a plain prompt, and the table records, per case, whether a turn started and how long it took (the measured v2 version is named); (2) the result is a table in `docs/switchboard.md` and a committed fixture of the answers (no secret, no session id of a real agent); (3) a fake v2 in the test suite reproduces each measured behaviour (an idle session that ignores a queued item, one that starts a turn from it), and a test shows which delivery the daemon uses for a wake to an idle session in each case; (4) if the measurement shows that a plain prompt (or another form) starts a turn where `queue` does not, the delivery of a wake to an idle agent uses it (the change is part of this ask, with the #1337 safety net unchanged); if `queue` with `resume` already starts a turn in every idle case, the docs say that the cause of the recorded case was the ended-turn state and the safety net is the whole fix; (5) tests with mutants (the wrong delivery for an idle agent, the fake ignoring a form) and a table-derived completeness test over the delivery forms, and the docs say it. The measurement session is created and removed by the test run's own helper and never touches a fleet agent's session.
