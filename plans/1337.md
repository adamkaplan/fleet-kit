### Cause (clause 1, stated first)
`Switchboard.deliver` (`bin/fleet-switchboard`, about line 4831) composes the message and admits it with `self.v2.synthetic(session, text, meta, resume, delivery, message_id, description)` (about line 4895). For a wake `resume = True` and `delivery = "queue"` (about line 4873); it becomes "steer" only when `steers_into_turn` says the agent is busy. A queued synthetic message sits in the session's inbox: whether an idle session then starts a turn from its inbox is the session's own business, and the daemon does not look again. Right after the write `deliver` calls `self._acknowledge(keys)` (about line 4917, and `self.sent.confirm` in light mode): a key counts as delivered once v2 ADMITTED it, not once it appeared in the transcript. The next pass reads `delivered_keys` (about line 4722; inbox and messages, or the ledger in light mode), finds the keys, drops them from the pending set in `_plan_pending` (about line 4800), and plans nothing. So the status line can show "4 pending: wake" while the audit shows admitted deliveries. Nothing retried or escalated because no code compares an admitted wake's age with the transcript. The only automatic recovery is `resume_first_recovery` (about line 14651), which reads a provider error (HTTP 499, ECONNRESET, timeout) after an ended turn and calls `resume_ended_turn` (about line 14598), which refuses an open permission request or question, a working session, and a resume within `RESUME_SECONDS` (10 minutes, about line 14577). A wake that starts no turn has no error, so it never reaches that path. The plan confirms this from the code; the recorded case (an idle agent, several reminders pending for many hours, cleared by a manual resume) fits it.

### Approach (what, not how)
A pass looks at each idle agent with a wake the daemon admitted with `delivery: queue` whose keys are still not in the transcript. When the oldest such wake is older than a configured time (default 15 minutes, one config key) and the reminder is due, the agent is resumed through `resume_ended_turn` (same refusals, same rate record, one resume per agent per incident) with one audit line naming the agent, the oldest pending age and the keys. An incident is kept per agent and ends when the keys appear. If the keys are still absent after a second configured time, the Chief of Staff is told once per incident with one line (agent, age, count). A working or blocked agent, and a reminder not yet due, are never resumed by this rule.
