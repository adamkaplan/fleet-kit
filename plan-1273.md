## Cause (clause 1)

From the code: bin/cloud_channel.py line 37 pins NAMESPACE = "fleet-agents". It is the default of handle (line 72), the default of make_secrets_reviewer (bin/cloud_hub.py line 99), and the namespace passed to agent_of in the RESERVED check (line 267), the CAPTAIN check (line 274) and the decisions scoping (line 316). The hub runs in namespace cw (cloud/k8s/cloud-hub.yaml, every object) and the launcher names agents for cw. The live hub runs in secrets mode, where the prefix is only a label, so nothing is broken today; in token-review mode an account of cw would be refused and one of a namespace named fleet-agents accepted. A copy of cloud_channel.py also sits under cloud/worker/bin/ (same constant).

## Every hit of 'fleet-agents' (git grep on integration) and its decision

- bin/cloud_channel.py lines 20, 37: docstring and constant. Decision: the constant is removed; handle takes the namespace as a required parameter; docstring names the setting.
- cloud/worker/bin/cloud_channel.py lines 20, 37: the worker's copy. Decision: kept in step with bin/ (same edit) so the two copies stay identical.
- bin/cloud_hub.py: no literal, uses cloud_channel.NAMESPACE at lines 99, 267, 274, 316. Decision: all four take the one value read at start.
- docs/cloud-channel.md lines 48, 59, 171: name the namespace. Decision: reworded to the setting (value cw in the manifest).
- bin/test-cloud-channel lines 52, 58, 62, 63 and bin/test-cloud-channel-server lines 49, 52: fake review users. Decision: the tests pass namespace "fleet-agents" explicitly to the library; the users are not edited.
- bin/test-cloud-hub lines 46, 276, 403, 415, 459, 536, 564: fake review users (7 line groups). Decision: unedited; the hub under test is given the setting fleet-agents (see U1).
- cloud/launcher/ (cloud_worker.py, hub_registry.py): no hit. cloud_worker.py takes CW_CLOUD_NAMESPACE (default cw) and builds the agent URL from it (hub_agent_url). Decision: no change (open choice d).

## Test method

New test methods and classes in bin/test-cloud-hub, in the existing style: source mutation helpers, loopback hub, fake reviewers. New test in cloud/launcher/tests/test_cloud_hub_manifest.py for the manifest value. Tests pass the namespace explicitly to library functions.

## Open choices (one recommendation each)

- (a) Required versus defaulted. Recommendation: required in token-review and secrets mode (when FLEET_CLOUD_CHANNEL_LISTEN is set); missing or malformed stops the hub at start with the named line "cloud-hub: FLEET_CLOUD_AGENT_NAMESPACE missing or not a namespace name"; library functions have no silent default to the old name. Cost: any other launcher of the hub must set it; the three existing serve() calls with a listener get the setting added.
- (b) Name: FLEET_CLOUD_AGENT_NAMESPACE (decided). Cost: none; it follows the FLEET_CLOUD_HUB_* family.
- (c) Manifest value: a literal "cw" in the env block, equal to the manifest's own namespace, with a test that the two agree. Recommended over the downward API. Cost: a second literal in one file, guarded by the test.
- (d) Existing agent records: the launcher's registry writer puts no namespace prefix of an account in names (it takes CW_CLOUD_NAMESPACE, default cw, only to build the pod URL), and a registry written by it keeps working unchanged. No change in the launcher or hub_registry.py. Cost: none. Any registry that names fleet-agents by hand must be rewritten to cw before token-review mode is turned on; secrets mode is unaffected.

## Out of scope

Switching the live hub to token-review mode, changing the secrets file format, the network manifest, the launcher, any other service.
